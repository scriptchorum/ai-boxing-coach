# 女性搏击视频复盘项目可行性分析

评审日期：2026-10-18。依据：用户提供的 V0.1 策划书、用户在本聊天中确认的资源条件，以及本文末尾的官方资料。本文件是立项判断，不是已完成的算法实验报告。

## 结论

值得做一个范围严格受限的验证项目。以女性身体为核心、单人手机录像、训练后复盘这三个方向保留。当前团队是用户本人每周约 20 小时，加 Codex 辅助；没有兼职教练。近期目标应是“女性后手直拳动作观察工具”，而不是已经能可靠判断动作对错的 AI 私教。

先证明三件事：在不同女性身体比例和服装条件下能看清动作；能稳定分出每一拳并定位证据；用户愿意用这些观察结果再次录像。专业技术评价、个性化纠错练习和收费教练服务，需要另外建立专家复核与效果证据。Codex 可以实现算法、工具和测试，不能充当独立的执教验证人员。

建议投入第一阶段 76–120 小时，另留 25% 余量；按每周 20 小时约 5–8 周。通过验收后再继续到可供少量女性用户试用的观察版 Alpha。完整任务预算见 [执行方案](EXECUTION_PLAN.md)，这些都是规划估算，尚无本项目实测速度。

## 必须保留的女性主体定位

产品首先服务女性训练者，不是通用产品加一个性别筛选器。女性的肩髋比例、臂长、躯干比例、身体轮廓以及衣着遮挡，是数据采集、质量检测、界面测试和验收的主要覆盖维度。第一阶段不采集与动作分析无关的胸围、体重或生理周期，不从视频推断性别。

女性应占招募参与者至少 70%，计算人数而非视频条数；若资源有限，首批全部为女性也可以。男性对照是后续可选项，不能挤占女性主样本预算。最终判断以女性样本的可用率、关键点误差、分段效果和复用反馈为主，不能用总体平均数掩盖女性某一体型或服装组的问题。

这是一项明确的产品要求，还不是“已证明对女性更准确”的宣传结论。Google 的相关模型卡已包含女性评估样本，因此不能把现有姿态模型一概描述为仅在男性上训练；本项目必须验证的是女性搏击场景中的实际表现。[模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20BlazePose%20GHUM%203D.pdf)

## 对原策划书的主要修正

| 原设想 | 评审意见 | 执行处理 |
| --- | --- | --- |
| 8 周完成三类拳法与 20–50 人 Beta | 对每周 20 小时且没有教练的团队偏乐观 | 第一个 5–8 周只承诺技术 Demo；多动作和公开 Beta 后置 |
| 现成姿态框架能支撑第一版 | 能提供基础能力，不能证明高速拳击质量达标 | 先做真实视频基准与拒绝分析机制 |
| 肩髋旋转、重心、后脚驱动都能评分 | 单目深度、遮挡与投影会影响可观察性 | 首期保留时间和二维可观察量；旋转与驱动暂作研究项 |
| 女性覆盖是差异化 | 必须成为主要验收对象，而非辅助标签 | 女性主体招募和独立留出测试写入验收 |
| 证据帧加 drill 构成明显竞争优势 | 同类竞品已经宣称具备类似能力 | 用可复核准确性、女性场景数据和复用表现证明价值 |
| LLM 把规则转成建议 | 可做，但不是验证的必要条件 | 首期使用确定性文字模板，不接付费 LLM |
| 先安排 1–2 名兼职教练 | 与实际资源不符 | 观察工具先行；专业评价设独立准入条件 |
| 30–50 段视频验证可行性 | 足够发现问题，不足以证明通用可靠性或公平性 | 按参与者和拍摄场次切分，开发集与留出集隔离 |

## 技术能力分级

| 能力 | 当前判断 | 主要限制与处理 |
| --- | --- | --- |
| 视频解码、骨架叠加、关键帧浏览 | 较高可行性 | 需要处理手机旋转、变帧率、镜像、格式与尺寸 |
| 单一后手直拳分段与计数 | 中等可行性，待实测 | 连打、假动作、遮挡可能合并或拆错；输出有效次数与拒绝次数 |
| 回手到初始手位区域的时间 | 条件可行 | 只描述可见手腕回到个人起始区域的时序，不等同于“防守合格” |
| 同场次动作重复性 | 条件可行 | 相同机位、站架和指标版本下比较；稳定不代表技术正确 |
| 女性身体比例适配 | 可实现并可评估 | 使用个体归一化与分组验证，不设置统一女性角度模板 |
| 肩髋轴向旋转及先后驱动 | 风险较高 | 二维肩线斜率不等于水平旋转；近侧与远侧遮挡会改变估计 |
| 后脚发力、真实重心、拳力、受伤风险 | 首期不成立 | 脚部像素移动不是地面反作用力，髋中心也不是真实质心 |
| 站架纠错、刺拳、1-2、泰拳动作 | 后续研究 | 每增加动作都要增加事件定义、样本、规则和独立验收 |
| 实时语音教练与全平台应用 | 当前不做 | 没有先验证离线质量，增加实时链路不能解决测量误差 |

MediaPipe 支持图像和视频中的身体关键点，并提供 33 点及估计的三维输出；MoveNet 提供 17 点，可用于上肢可见性和速度对照。[MediaPipe 官方说明](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker)[MoveNet 官方说明](https://www.tensorflow.org/hub/tutorials/movenet) 这些是框架能力，不是拳击测评结果。相关模型卡明确把精确度量深度的应用列在范围外；单目三维研究也指出深度歧义和自遮挡问题。[模型卡](https://storage.googleapis.com/mediapipe-assets/Model%20Card%20BlazePose%20GHUM%203D.pdf)[单目三维研究](https://arxiv.org/abs/2107.13788) 据此，本方案不把模型输出的米制坐标当成经过标定的拳速或生物力学真值。

## 当前资源下的关键风险

| 风险 | 早期信号 | 处理方式 |
| --- | --- | --- |
| 没有专业复核者 | 规则只有用户或 AI 的主观解释 | 输出描述性观察；不发布“错误”“合格”“纠正练习”结论 |
| 没有足够女性授权样本 | Demo 只有一个人的同机位视频 | 可以做工程演示；不能声称女性泛化达标，暂停扩大产品承诺 |
| 手腕高速模糊和遮挡 | 峰值附近丢点，计数波动 | 优先改拍摄规范；达不到门槛则降级为手动分段浏览 |
| 为高准确率而大量拒绝 | 只在少数最好看的视频上给结果 | 必须同时报告覆盖率、拒绝率和条件准确率 |
| 个体归一化出错 | 机位变化导致“身体比例”突变 | 只用稳定起始帧的可见尺度，不估计真实骨长 |
| 同一人视频泄漏进测试集 | 调阈值后所有测试都很好 | 按参与者切分；公开记录开发集与测试集版本 |
| 多电脑覆盖进度 | 两边同时改 main 或交接记录 | 一次只在一台开发；任务登记、提交、推送后再换机 |
| 方案扩张 | 还没有分段评估就开始加支付或泰拳 | 以阶段门禁决定后续投入，不按周历强行上线 |
