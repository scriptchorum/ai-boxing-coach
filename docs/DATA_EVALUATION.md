# 女性主样本数据与验收规范

状态：T01 冻结的验证协议 v0.1；没有真实采集或评估结果。所有验收门槛是项目初始提案，不能解释为临床或执教标准。模型与规则阈值须在开发集上校准并在独立测试前冻结；验收门槛变更须记录新版本，不能为通过测试而事后修改。当前证据见 [GATES.md](GATES.md)。

## 女性身体为主要设计对象

按参与者人数确保女性至少 70%；首批全女性可以接受，男性对照可后续补充。参与者为自愿参与的成年人，性别信息由本人选择提供，不从面部、声音、穿着或骨架推断。招募记录由用户私下管理，拒绝提供非必要信息不影响使用。

覆盖重点：

- 肩宽相对髋宽、臂长相对躯干长度、身高与画面尺度的不同组合。
- 不同身体轮廓下肩、髋、肘、手腕的可见性；不把胸部轮廓当作姿态或体型优劣指标。
- 日常运动内衣外搭、贴身上衣、宽松上衣、长袖等穿着；不要求受试者为算法改变遮蔽程度。
- 正架和反架、不同练习熟练度、不同手机和拍摄场次。
- 光线、机位和动作速度变化；先控制机位，再扩展复杂环境。

身体尺度优先从同一条视频的稳定起始姿势估算为相对量，并记录可见性和机位；这些不是身体的真实尺寸。首期不要求体重、胸围、经期、孕产状态、伤病或健康史。怀孕/产后、疼痛或康复指导不在观察版范围内，不能借女性定位延伸为医疗建议。

不能仅按“女性/男性”两组平均数评价覆盖。女性内部的服装与尺度组也要列出样本数和错误分布。单组少于 5 名独立参与者时只记录探索结果，不宣称通过公平性验证。小样本、不完整覆盖和未采到的组必须明确列出。

## 素材分阶段准备

| 阶段 | 目标素材 | 用途与限制 |
| --- | --- | --- |
| 起步试片 | 3–5 条，用户本人或自愿参与者，女性优先 | 只调试导入与拍摄方法，不能宣称人群适用 |
| Demo G1 | 至少 10 条规范片，至少 3 人，女性人数 ≥70%；另 5 条坏片 | 证明管线能运行；不代表算法可靠性已验证 |
| Alpha 开发 | 建议 10–15 名女性、40–80 条短片，分多场次 | 调分段和质量阈值；这是工作量估算假设，招募不足需顺延 |
| Alpha 独立留出 | 另外至少 5 名女性、20 条规范片、100 次可标注动作，另至少 20 条预先定义坏片 | 人员不得与开发集重合；无法满足时维持演示状态 |
| 专业反馈版 | 另外建立教练标注集和独立试验 | 样本量按错误类型与复核分歧再定，不沿用 Demo 的成功率 |

同一个人同一天拍几十条不能替代多人样本。同一个视频的裁剪片、镜像版、重编码版和相邻动作必须在同一数据分区。预训练姿态模型可以直接使用；本项目的规则阈值和归一化设置也属于需要隔离测试的数据驱动选择。

参与者自愿提供自然动作；不要求初学者刻意做可能危险的“错误动作”来补齐标签。已有授权之外的网络课程或公开视频不自动成为训练素材。

## 拍摄和质量门禁

输入先约束为单人后手直拳影子拳，静止手机、全身可见、画面留边、无前景遮挡。站架、镜像、动作类别由用户确认。起始保留约 1–2 秒自然准备姿势，不据此判断姿势“标准”。每段以 5–10 次可分辨动作为采样目标，不要求加速或加力。

下列情形进入拒绝或部分可分析状态：无法解码、超出支持长度/尺寸、多人、人物出框、关键部位持续遮挡、明显模糊、机位不支持、重复/倒退时间戳、无法确定回位事件。默认只检测到一个人不证明画面没有第二个人，T06 需检查多人体检测能力或采用保守拒绝策略。

每个指标单独判断关键点可用性，不用“总体姿态成功”掩盖手腕丢失。visibility/presence 是模型信号，不是“教练判断有 90% 正确”的概率。阈值只在开发集上选择；应用模型、阈值与数据版本必须记录。

短缺失可在明确记录的条件下插值，例如不超过 2 个 30fps 帧的等效时间；峰值或回位边界缺失时不得用插值伪造事件。超过范围则返回不可分析。这个插值上限也需要开发集验证，不是固定生理标准。

## 指标定义与不可越界的解释

| 指标 | 计算或事件定义 | 允许解释 | 禁止等同 |
| --- | --- | --- | --- |
| 动作分段 | 起始到回位；使用手腕相对躯干轨迹和肘角变化建立状态机 | 检测到第 N 次后手直拳候选 | 该拳有效击中或正确 |
| 最大可见伸展 | 手腕相对同侧肩的投影距离在动作内达到峰值，结合肘角去抖；人工标注同一定义 | 可见轨迹上的伸展时刻 | 真实三维最大伸展或接触瞬间 |
| 回手到起始区域时间 | 从最大可见伸展到手腕回到该片起始参考区域并保持至少 100ms；区域由开发集选定相对尺度阈值 | 回到该片初始手位的估计时间 | 防守合格、回手快慢是否专业 |
| 重复性 | 同场次至少 5 次有效动作的中位数及四分位距，必要时展示每次值 | 这组动作更一致或更分散 | 一致就代表技术正确 |
| 躯干投影偏移 | 二维髋中心相对可见脚部参考与起始位置的变化，按可靠躯干尺度归一化 | 画面内身体投影改变 | 真实重心、平衡能力、受力或前扑判错 |
| 肩髋与足部旋转 | 仅作研究曲线，不进入首期用户结论 | 当前机位下的可见几何变化 | 水平轴向旋转角、发力链或拳力 |

二维计算前先恢复像素比例：x_px=x_norm×图像宽，y_px=y_norm×图像高。不能直接在分别按宽、高归一化的坐标上计算真实二维角度。镜像仅影响显示；保留解剖左右映射和站架定义，不能按画面左手猜测后手。

时间使用解码后帧的显示时间戳 PTS，统一从首帧计时；保留原始帧号和时间映射。变帧率视频不能使用 frame_index/固定 fps 代替时钟。若重采样必须记录映射，不重复帧伪造分辨率。30fps 的时间间隔约 33.3ms，60fps 约 16.7ms，界面不得暗示达到 1ms 测量精度。FFprobe 可提供媒体与逐帧信息，[官方说明](https://ffmpeg.org/ffprobe.html)。

WorldLandmarks 的髋中心是随人体移动的参考原点，不是固定场地坐标。不能用其髋中心位移直接求身体在场地中的运动；也不能把估计三维数值直接当作标定后的速度和力学数据。相关限制参见 [可行性分析](FEASIBILITY.md)。

## 最小数据契约

T01 已将前四类接口落实为 [正式契约](CONTRACTS.md) 和 [可运行 schema](../schemas/contracts.schema.json)，配有结构与语义校验。下面是概要；完整字段与命名以该版本 schema 为准。ReviewAnnotation 在 T08 落实。真实逐人记录保存在本机 data 下；Git 只保存 schema 和合成示例。

- VideoManifest：sample_id、匿名 participant_id、session_id、文件 SHA-256、时长、编码、宽高、PTS 来源、站架、镜像、人工机位、数据分区、授权状态引用；不存真实姓名或联系人。
- PoseSequence：schema_version、sample_id、model_id 与哈希、运行配置、原始帧号、timestamp_ms、归一化坐标、可选估计 world 坐标、visibility、presence、缺失与插值标记。
- ActionSegment：action_id、start_ms、extension_ms、return_ms、手别、状态、人工/自动来源、质量理由；缺失事件用 null，不能用 0 冒充。
- ObservationReport：input_hash、schema/model/rule/app 版本、样本条件、候选数、有效数、有效比例、观察项、数值与单位、证据时间和帧、不可分析理由、生成时间。
- ReviewAnnotation：标注者代号、可分析状态、事件时刻、歧义理由、复核状态；观察版不收集未经复核的“动作正确”金标准。

原始视频导出、图像导出和逐帧骨架都可能包含可识别或身体相关信息，不能因去掉姓名就认定匿名。日志只记录任务 ID、耗时和错误码，避免记录视频路径、画面、身体属性和密钥。

## 评估方法与门槛

先冻结 participant_split、模型版本、阈值配置和指标定义，之后只在独立留出集运行。若看过测试错误并据此调参，该集转为开发集，另准备新留出集。

1. **分段 F1**：按预测区间与人工区间的时间 IoU ≥0.5 一对一匹配，未匹配预测是 FP、未匹配人工动作是 FN。报告 Precision、Recall、F1，并给每位参与者的结果；G2 目标 F1 ≥0.85。即使系统拒绝片段，可人工标注的未识别动作也计为 FN，不能从总体事件评估里悄悄移除。
2. **计数误差**：每条规范片的预测动作数与人工数之差取绝对值再平均，目标 ≤1；同时报每片值、最大值、完全拒绝数量。
3. **时刻误差**：对匹配且可分析动作比较事件时间的绝对误差，回手时间 MAE 目标 ≤100ms，同时报 P90、有效动作数和人工标注歧义。它是条件指标，不能脱离拒绝率单独发布。
4. **覆盖率**：独立规范片中，至少有 5 次有效动作且所有启用指标均能出结果的片数/规范片总数，目标 ≥70%；同时报告部分可用比例、动作级有效比例及原因分布。
5. **坏片拒绝**：在至少 20 条预先分类坏片中，应拒绝的片子被拒绝的比例目标 ≥90%；同时在规范片上报错误拒绝率。坏片类别至少含出框、遮挡、模糊、多人和不支持格式，不靠一种错误凑数。
6. **女性内部表现**：先列人数、片数、动作数，再列衣物/机位/尺度组指标；用参与者级重采样区间或逐人结果呈现不确定性。组间差距超过 10 个百分点是调查触发点，不是自动证明歧视或不公平。
7. **运行性能**：在记录型号的测试电脑上，目标 30 秒标准视频端到端 P95 ≤60 秒，固定至少 20 次运行并区分冷启动；若设备达不到，给真实进度和等待提示，不能借用官方模型 FPS 当作本产品性能。

用户可以标注“什么时候开始/伸展/回到起始区域”，但这不是专业动作质量标签。先抽 10 条视频隔一周盲重标，报告自一致性和歧义；它不等于第二位独立标注者。后续技术判错必须有专业人员定义规则和复核，按错误类型分别评估误报与漏报。

## 可用性与复用统计

先邀请 5–8 位成年女性，自愿参与、清楚知道这是观察工具。记录是否独立导入并理解报告、是否将观察误读为技术诊断、是否愿意再次使用。访谈不能把“觉得有趣”当作购买意愿。

7 日复用率的分母是首次完成有效报告且已经有完整 7 天观察窗口的独立参与者；分子是 7 天内主动产生第二份有效报告的人。提醒后返回与主动返回分开计数，用户本人和开发测试不计入外部复用。报告原始人数（例如 3/7），不只报百分比。不追踪尚未成熟的 7 天窗口，更不在第 8 周宣布已经获得 30 日留存。

## 数据治理与两台电脑

默认离线使用，用户挑选文件不等于同意上传。视频与音频不发送给 LLM。临时帧分析后删除，显式“保留本地历史”才保存报告或引用；原始导入文件不因删除报告自动从用户文件夹删除，界面应区分报告、缓存和用户原始文件。

真实受试数据另行授权存储和传输，限定用途、访问人、保留期限与退出删除流程。首次试用前把实际实现与说明核对。数据是否跨境、发布地区和适用要求在云端功能规划时单独核查，本方案不宣称已经合规审定。

Git 同步代码和非敏感实验配置；只提交经过审查的合成数据和汇总结果。模型下载清单保存版本与哈希，模型本体本地下载。另一台电脑必须分别装依赖、下载同版本模型，并获得相同受控样本，不能只靠 git pull 就声称实验可复现。
