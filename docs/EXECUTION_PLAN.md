# 女性搏击视频复盘执行方案

版本：0.3。日期：2026-10-18。状态：T01 数据契约与校验已完成，视频分析应用尚未开始。

## 已确认条件

产品以女性身体为主。用户本人每周可投入约 20 小时；Codex 辅助分析、编码、测试与文档；目前没有兼职教练。授权视频、设备配置、编程熟练度和目标发布地区尚待确认，不能按已经具备计算。

执行计划已转入 T01 契约实现，下一开发任务是 [任务清单](BACKLOG.md) 的 T03；T02 素材由用户录制中，尚未核验。不把契约校验通过当作应用或视觉效果完成。

## 范围和用户体验

首个版本服务成年女性的个人后手直拳影子拳录像。用户手动选择正架或反架、确认镜像和机位，导入 10–30 秒固定机位视频。系统检查质量，显示可用动作、关键帧、手腕回到个人起始手位区域的时间，以及同场次的动作差异。站架只作为输入和参考姿势，不单独给技术分。

画面建议全身可见、双手和双脚留边、光线充足、无沙袋遮挡。Demo 比较侧面与前侧约 45 度机位，再用样本决定第一版支持哪一个；不声称一个角度能测全部指标。先支持 720p 或 1080p、30/60fps 的常见视频；具体容器与编码范围由 T04 检测并写进说明。不是强制所有手机录制 60fps。

首屏与报告必须体现女性身体多样性，但不对体型作审美评价、不推断性别、不设置统一“女性标准骨架”。报告没有已验证发现时可以是零条观察，不能为凑出 1–3 条而编造问题。

### 观察版必须有

- 逐帧姿态与原视频对应，保留真实时间戳和质量信息。
- 明确显示“有效动作数 / 候选动作数”，可人工修正分段并标明修正来源。
- 每条观察关联动作编号、时间、证据帧和局限；缺数据返回无法分析。
- 女性样本单独评估，衣物和身体比例覆盖记录可追踪。
- 本地报告和历史；可导出、可删除，默认视频不上传。
- 两台电脑可用同一份代码和版本配置复现合成样例。

### 本阶段明确后置

刺拳、1-2、沙袋、泰拳、实时语音、原生手机 App、订阅支付、社交、云端账号历史、个人训练计划、LLM 报告、自训练模型、真实拳力或伤病风险评分。未经专业复核的“动作好坏”和个性化纠错练习也后置。

女性主体定位不后置；后置的是证据不足的身体或健康推断，例如自动推断生理周期、痛症、体脂或性别。

## 工时与排期

下表工时是规划估算：包含用户需要参与的需求确认、环境处理、素材整理、开发验证、标注和试用反馈，已假设 Codex 辅助。不是把 Codex 算成第二名每周 40 小时的工程师，也不是模型运行分钟数。没有人类执教的专业工作不计作已覆盖。

| 里程碑 | 任务 | 基础工时 | 加 25% 余量 | 以每周 20 小时换算 |
| --- | --- | --- | --- | --- |
| 技术 Demo | T01–T07 | 76–120 小时 | 95–150 小时 | 约 5–8 周 |
| 可用观察版 Alpha 的后续工作 | T08–T16 | 118–194 小时 | 147.5–242.5 小时 | 额外约 8–13 周 |
| 从零累计到 Alpha | T01–T16 | 194–314 小时 | 242.5–392.5 小时 | 累计约 13–20 周 |

单阶段周数向上取整后不能直接相加代替累计工时换算。每周 20 小时是总投入，不再额外假设用户有时间做招募和标注。表中包含操作时间，不包含无法并行消化的等待；样本招募、7 天回访和网络问题会延长日历时间。未设绝对上线日期。第一周完成后按实际任务耗时校正；如编程与环境上手超出预留，缩范围或延后，不承诺 AI 固定加速倍数。

### 分阶段推进

1. **启动与素材**：T01–T03，确定观察版范围、字段与首批授权素材，建可复现工程。没有真实视频时可以用合成数据开发接口，但不能算完成视觉验证。
2. **技术 Demo**：T04–T07，先打通视频到姿态、质量检查、骨架与证据帧。达到 G1 才投入完整分段。
3. **观察指标**：T08–T10，标注事件，建立留出集，验证分段与时间测量。达到 G2 才包装完整报告。
4. **少量试用**：T11–T16，本地历史、删除、复现、女性用户试用和复盘。达到 G3 才考虑增加动作或寻找专业复核合作。
5. **专业反馈版**：另立范围，取得复核人员和数据后评估，不能自动启动。

首期不购买 GPU，不把付费 LLM 作为依赖。现金费用按实际发生的参与者补贴、存储或设备支架记录；这些是待确认支出，不是已有预算授权。专业反馈版需另估开发约 60–110 小时、教练标注与规则复核约 24–40 小时，再加招募和至少 2 周用户观察；这只是预估，不计入本方案的观察版工作量。

## 阶段门禁

所有数字都是项目门槛，不是行业标准或已达结果。T01 已将其冻结为 [v0.1 验收基线](GATES.md)，调整时记录原因，不能见到测试结果后只改门槛。

| 门禁 | 通过条件 | 不通过时 |
| --- | --- | --- |
| G0 范围与数据准备 | 女性主体范围、事件定义与本地数据规则确定；首批素材存在且有授权 | 素材不足只做合成接口，不报告识别效果 |
| G1 技术链 | 至少 10 条符合规范的真实视频来自至少 3 人，女性人数占至少 70%；至少 9 条完成解码至预览；另有至少 5 条坏片走明确失败路径；手工核对时间和骨架 | 改机位/格式或缩为手动浏览；若只有一位参与者，维持个人演示状态 |
| G2 观察可信度 | 独立女性留出集至少 5 人、20 条视频、100 次可标注动作；事件分段 F1 ≥0.85；每条视频计数绝对误差均值 ≤1；已接受样本回手时间 MAE ≤100ms；符合规范视频完整可分析率 ≥70% | 定位失败模式；关闭不可靠指标，不通过则保留人工分段 |
| G3 可用性 | 5–8 名女性试用；至少 80% 无远程代操作完成一次导入与报告查看；至少 4 人能正确解释一条观察及其限制；7 天后按原始人数报告复用和退出原因 | 优先修改流程或价值表达，不用“AI准确率”掩盖无人复用 |
| G4 专业评价准入 | 有具备搏击执教经验的复核者、可追溯规则和 drill 审核；部分样本有第二人独立复核；另设独立测试 | 不上线个性化技术判错、技术总分和纠正练习 |

G3 小样本中的“至少 3 人在 7 天内主动再次分析”仅作为继续访谈的积极信号，不能证明市场成立；不足则先访谈 5 人再决定是否继续。G2 细节、指标分母与拒绝样本处理见 [数据与验收](DATA_EVALUATION.md)。G4 当前是资源依赖，不阻止 G0–G3 的观察工具开发。

## 建议技术方案

先使用桌面本地 Python 分析核心，配一个本地浏览器界面；手机仅负责录制和传入文件。建议 MediaPipe Pose Landmarker + FFmpeg/FFprobe + OpenCV/NumPy；简单 Streamlit 本地界面即可。版本在 T03 根据 Windows 的实际兼容性固定到依赖锁文件，模型资产记录 URL、版本与哈希；不承诺未验证的 Python 或模型版本。

分析核心与界面分离，方便后续改成 Web/PWA。首期不同时维护 React、云端队列和浏览器推理两套管线。浏览器端迁移是独立任务：官方 Web 指南提示推理调用会阻塞主线程，需要工作线程等设计，不能把 Python 版本完成视作移动端已经可用。[官方说明](https://developers.google.com/edge/mediapipe/solutions/vision/pose_landmarker/web_js)

接口分四层：VideoManifest（媒体与时间轴）、PoseSequence（点位与可见性）、ActionSegment（动作与事件）、ObservationReport（观察、证据、拒绝原因和版本）。正式字段及校验命令见 [CONTRACTS.md](CONTRACTS.md)。将来的报告生成不应依赖 LLM、账号系统或数据上传；当前只有合成报告契约。

## 多设备协作方法

同一时间只让一台电脑修改 main。在 BACKLOG.md 登记任务、当前设备别名和状态，推送登记后开始工作；另一台先拉取并查看登记。设备名用 A/B，不记录用户名或私人目录。

每次结束更新 HANDOFF.md：任务 ID、实际改动、运行过的检查、未解决问题、下一步。任务完成需要代码或文档产出与验证证据，不能凭“生成了文件”标为 Done。

代码、锁文件、规则、非敏感文档进 Git。真实录像、逐人标注、身体信息、同意记录、密钥和本地数据库单独保存；两台电脑需要相同素材时，由用户选择受控传输方式。开发项目同步不代表未来产品用户的训练历史已经具备跨设备同步。

推荐下一次发给任一电脑 Codex：

> 先同步仓库并读取 AGENTS.md、docs/HANDOFF.md 和 docs/BACKLOG.md。T01 已完成，从 T03 建立可复现工程骨架，保持女性身体为核心、每周 20 小时、无兼职教练的约束。复用已有契约校验，不把合成样例视作视觉验收。完成后更新任务与交接，提交并推送。
